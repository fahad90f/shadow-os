# Packaging input for the NEXUS Arsenal packages

Nothing in this directory is used by the build directly; it is the input for
`debian/` of the `nexus-os` source package.

| File | What to do with it |
|---|---|
| `control.in` | Generated by `../tools/gen-control.py`. Merge its stanzas into `debian/control`. `gen-control.py --check` fails when it is stale. |
| `nexus-arsenal-data.install` | Copy to `debian/nexus-arsenal-data.install`. |

## Who owns what

| Package | Architecture | Content | Built by |
|---|---|---|---|
| `nexus-arsenal` | any | `/usr/bin/nexus-arsenal`, its desktop entry, `/usr/share/doc/nexus-arsenal/*.md` | CMake install component `nexus-arsenal` (component `manager`) |
| `nexus-arsenal-data` | all | `/usr/share/nexus/arsenal/profiles/*.json` (manifests, `categories.json`, `schema.json`, `sizes.json`) | `debian/nexus-arsenal-data.install` |
| `nexus-arsenal-<id>` | all, or any when a tool is architecture-specific | nothing (metapackage) | `debian/control` only |

The manifests belong to **`nexus-arsenal-data`**, not to the manager: the
metapackages depend on the data so that a profile installed with plain `apt`
is still described on the system, and that must not pull in a Qt application.
`arsenal/manager/CMakeLists.txt` also installs the manifests into the CMake
install component `nexus-arsenal-data`; that is for developer trees
(`cmake --install`) and is not what the Debian package is assembled from,
because the architecture-independent build does not configure the compiled
components.

## Things `debian/` has to take care of

* `debian/rules` installs one CMake component per package returned by
  `dh_listpackages -a` and fails when a component installs no files. A
  metapackage that is `Architecture: any` (currently `nexus-arsenal-reversing`,
  because `edb-debugger` exists on amd64 only) is in that list and is empty by
  design: skip packages matching `nexus-arsenal-*` other than `nexus-arsenal`
  itself in `install_components`.
* `distro/repositories/components.conf` sends `nexus-arsenal-*` to the
  `security` component. That pattern also matches `nexus-arsenal-data`, while
  `nexus-arsenal` (the manager) goes to `core` and depends on it. Either add a
  line `nexus-arsenal-data core` before the pattern or make sure the `security`
  component is enabled wherever the manager is installed.

The reasoning for `Architecture`, `Depends` and `Recommends` is in the
docstring of `../tools/gen-control.py`.
